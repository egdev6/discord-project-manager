# v0.3.0 internal fake-first/local baseline

v0.3.0 is an internal fake-first/local baseline for Discord admin UX and OpenClaw-to-Gentle SDD routing. Production readiness is not claimed.

This release promotes the `develop` v0.3 work to `main` after the v0.2.0 runtime governance baseline. It keeps private Discord-to-Engram write/readback deferred under #211.

## Completed scope

### OpenClaw-to-Gentle SDD skill development

- #190 via PR #244 — defined `openclaw_skill_development` as a governed OpenClaw-to-Gentle SDD handoff for repo-backed skill contracts under `skills/{name}/SKILL.md`.
- The handoff remains proposal-only: OpenClaw classifies, resolves permissions, and gates writeback; Gentle SDD may propose artifacts, validation evidence, and sync/rebuild/restart requirements, but no Discord-originated write executes.

### Discord routing and operational advisor

- #214 via PR #245 — added `discord-general-advisor` as a response-only runtime-core skill and fake-first contract for routing and operational architecture questions.
- Advisor scenarios cover project, category, channel, context, skill, profile, capability, strategy, task, analytics, publishing, and ambiguity cases with `write_executed: false`.

### Discord admin UX fake-first baseline

- #196 via #246/#248 and PRs #247/#249 — split the high-risk admin UX epic into reviewable fake-first slices.
- #246 via PR #247 — defined the admin UX contract, sanitized scenarios, and validator for profile listing, scope bindings, profile bind/clone previews, effective runtime inspection, scoped skill/capability previews, and backup/export request routing.
- #248 via PR #249 — packaged a repo-safe synthetic admin UX preview harness in the OpenClaw image as `discord-project-manager-admin-ux-preview-harness`.

### Release workflow hygiene

- #242 via PR #243 — added the release roadmap hygiene skill so post-merge and post-release GitHub Project statuses distinguish `Merged to develop`, `Merged to main`, and administrative `Done`.

## Installation and configuration notes

- Use the pinned runtime defaults from the v0.2.0 baseline unless intentionally overriding them in local/private configuration.
- Keep `.env` local and out of git.
- The OpenClaw image now includes `discord-project-manager-admin-ux-preview-harness` for repo-safe synthetic admin UX preview validation.
- Do not publish real Discord guild/channel/user/message IDs, credentials, screenshots, raw logs, transcripts, private payloads, raw Engram exports, SQL dumps, backup archives, or volume dumps.

Validate local runtime configuration with:

```bash
docker compose config
bash scripts/validate-runtime-version-baseline.sh
bash scripts/validate-repo-safe-evidence.sh
```

## Migration notes

No data migration is required for this fake-first/local baseline.

The new admin UX and advisor surfaces are contracts, fixtures, validators, skills, and synthetic harnesses. They do not modify private runtime state by themselves.

## Rollback and fix-forward notes

If v0.3.0 promotion causes a regression:

1. Keep private data out of public evidence; record only sanitized summaries.
2. Revert the release PR on `main` if the regression is in tracked repository content.
3. If the issue is runtime configuration, restore the previous pinned image/configuration values locally and re-run:

   ```bash
   docker compose config
   bash scripts/validate-runtime-version-baseline.sh
   bash scripts/validate-repo-safe-evidence.sh
   ```

4. If private runtime state is affected, stop write-like Discord actions, use the private backup/restore runbook, and verify recovery with sanitized summaries only.
5. Open a follow-up issue before enabling any live admin command, private export, or write/readback path.
